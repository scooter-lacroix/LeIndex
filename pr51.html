    Merges two cross-reviewed feature lines into a single release at v1.9.5: the embed-merge (retire the leindex-embed subcrate into the root crate — one crate, two binaries) and the opt-in fragment-embeddings layer. Both lines were independently implemented, mutually cross-reviewed (APPROVE both directions), and reconciled at this merge commit.

    Co-developed by GrayHill (Agent A — embed-merge) and agent-b (Agent B — fragment-embeddings); mutually signed off post-merge.

    What ships

    Embed-merge (one crate, two binaries)

    • leindex-embed subcrate retired into root; worker source at src/embed/; root leindex-embed bin wraps leindex::embed::worker_main::run.
    • cargo install leindex --features onnx now installs both leindex and leindex-embed from the single root crate.
    • ort pinned to 2.0.0-rc.13 (load-dynamic deadlock fix); [patch.crates-io] git patch removed.
    • Truthful runtime provider selection (select_auto_from_availability: CoreML → MIGraphX → CUDA → CPU, resolved before session attach), .error_on_failure() with preserved GPU→CPU fallback; rocm is a deprecated alias routing to MIGraphX.
    • Strict feature DAG; unified src/config.rs shared by CLI + worker.
    • CI/release reworked for one crate (Linux compile matrix + macOS CoreML check, encoded job graph, retired-subcrate guard).

    Fragment embeddings (opt-in)

    • Tree-sitter semantic chunker (ported from Warp's full_source_code_embedding) + module-level orphan coverage.
    • Localized content-hash (blake3) store; idempotent, dedup'd incremental indexing; crash-self-healing persistence.
    • Fragment candidates union into the search pool, fuse as a renormalized score component, feed the existing local reranker.
    • Cache-key v2 folds fragment knobs + persisted root hash. setup --check surfaces the fragment knobs.

    Version

    1.9.5 (small-bump policy: 1.9.1–1.9.5 grouped in the changelog; fragment work folded into the 1.9.5 section, no separate sub-release).
